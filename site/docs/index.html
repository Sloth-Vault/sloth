How a slow vault works.

A SLOTH vault is a Squads v4 multisig on Solana with three keys. Any move needs two of them, then waits 24 hours, 3 days or 7 days on-chain before anyone can release it.

The point is time. A stolen key on Solana usually means an empty wallet within a second. In a SLOTH vault, a stolen key can only write a request, and that request needs a second signature and a full wait before a single lamport moves.

SLOTH holds no key and runs no contract of its own. This site builds transactions, your wallet signs them, and the Squads program enforces every rule below.

The threshold is 2 for everything: approving, rejecting and cancelling. A request created by one key already counts that key's approval, so it needs one more.

The chain stores keys sorted by address, not by name, so the app shows Full key for main and backup and Guardian for the vote-only key.

Choosing them

  • Main: the wallet you use most. It becomes the creator of the vault.
  • Backup: a separate wallet on another device, ideally a hardware wallet or a phone you don't browse with.
  • Guardian: someone who answers messages, or a third wallet of your own kept offline. A guardian can't start a move, but it can be the second vote on one.

Never reuse a seed phrase across keys. Three wallets from one seed are one key.

Create a vault

  1. Open the app and connect the main wallet (Phantom or any wallet that injects a Solana provider).
  2. Paste the backup and guardian addresses.
  3. Pick the wait: 24 hours, 3 days or 7 days.
  4. Tick the box and press Create vault. One transaction, signed by the main wallet.
  5. Copy the share link under Share with your other keys and open it on the backup and guardian wallets.

Creation costs only network rent and fees, about 0.01 SOL to be safe. Squads charges no creation fee. The settings are fixed with no admin: there is no config authority, so only the keys themselves can change the vault, through the same two-key and wait rules.

Deposit

The vault has two addresses. The vault address holds funds. The multisig address holds the rules and appears in your share link. Send funds only to the vault address shown under Deposit.

  • SOL: use the Deposit form or send from any wallet.
  • Tokens: a normal transfer to the vault address. SPL and Token-2022 tokens both work, and the vault shows every token account it owns.

Anyone can deposit. Only two keys and the wait can take it out.

Withdraw

ask

A full key fills New request: asset, destination, amount. The request and its first approval land on-chain together.

approve

A second key opens the vault and reads the same request from the chain: amount and destination. It presses Approve. The clock starts now.

wait

The request shows Waiting with a countdown. Nothing can shorten it. Two keys can still cancel.

release

After the wait, main or backup presses Release. Funds go to the address both keys approved.

If the app can't read a request as a plain SOL or token transfer, it says so and hides Approve. Requests made by other tools may hold anything, so don't approve what you can't read.

For tokens, the destination is the owner's wallet. The app creates their token account if it's missing, and reads the owner back when it shows the request.

Cancel or reject

Reject is a no vote on a request still waiting for its second key. Two rejects close it.

Cancel stops a request that is already approved and waiting. It also takes two keys. One cancel is shown as 1 of 2 cancels and the request stays live.

If a request you didn't make appears, assume one key is stolen. Cancel it with your two other keys, then replace the stolen one.

Replace a key

Under Keys, a full key presses Replace next to the lost key and enters the new address. That creates a key-change request, which follows the same path: a second key approves, the wait runs, then a full key releases it.

When it lands, every request still waiting for votes becomes void, including one a thief opened with the old key. A request that was already approved before the change can still be released, so cancel those with two keys.

The new key keeps the old key's role: a replaced guardian stays vote-only, a replaced full key stays full.

Without this site

Your vault lives in the Squads v4 program, not on slothvault.xyz. If this site disappears, open the multisig address with any Squads v4 tool, or with the open-source @sqds/multisig SDK, and sign with the same keys. The rules stay the same everywhere.

Keep a note of your multisig address somewhere offline. It's the part after # in your share link.

Limits

  • Two stolen keys beat it. Two keys can approve a move, and the third key can't cancel alone.
  • Two lost keys lock it. With one key left, nothing can leave or change. Funds stay stuck for good.
  • No fast lane. There is no emergency exit and no way to skip the wait.
  • Not private. The vault and every request are public on Solana.
  • Not audited. Squads v4 has its own audits. The SLOTH site and code have none. Start with a small amount.
  • The site doesn't change the wait. Choose it carefully when you create the vault.

Questions

Can SLOTH take my money?

No. SLOTH isn't a key on your vault and has no admin rights over it.

Can I use one wallet as two keys?

The app refuses duplicate keys. Two wallets from the same seed phrase pass, but they protect nothing.

What if my guardian goes missing?

Main and backup can still do everything, including replacing the guardian.

Can I change the wait later?

Not from this site. Squads tools can, with two keys and the current wait.

Does it work with Ledger?

Any wallet that can sign Solana transactions through your browser wallet works as a key.

Is this financial advice?

No.
